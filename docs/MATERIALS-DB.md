# מאגר מחירי חומרים — איך זה עובד

הבוט התמחור לא צריך לנחש כמה עולה כבל 5×6 או מא"ז 16A. המאגר הזה נותן לו את
המחיר האמיתי, מהמחירון של **ארכה (erco.co.il)** — ספק החשמל עם הקטלוג הרחב
בישראל.

## מה יש בפנים

| קובץ | מה זה | גודל |
|---|---|---|
| `data/materials/index.json` | האינדקס שהשרת קורא בזמן ריצה (עמודות, דחוס) | ~0.8MB |
| `data/materials/erco.json` | כל השדות, קריא לבני אדם ולבדיקות | ~4.6MB |
| `data/materials/taxonomy.json` | עץ הקטגוריות + סטטיסטיקת מחירים לכל ענף | ~0.2MB |
| `data/materials/raw/` | הקציר הגולמי מהספק (JSONL) — מקור האמת, לא נוגעים ידנית | ~40MB |

כל שורה במאגר היא **פריט שאפשר לקנות**: לא "כבל N2XY בגדלים שונים" אלא
"כבל 5X6 FR N2XY — 17.54 ₪ למטר, מק"ט 5951160".

## מאיפה זה מגיע

ארכה רץ על Magento 2, ונקודת ה-GraphQL שלו פתוחה לקריאת קטלוג. זה אומר:

* מקבלים **נתונים מובנים** במקום לפרסר HTML — כולל טבלאות "בחירת דגם"
  (כל חתך של כבל עם המק"ט והמחיר שלו).
* ~110 בקשות לכל הקטלוג במקום ~4,200 טעינות עמוד. גם מהיר וגם מנומס.

הקציר עובר שלושה שלבים:

```bash
python scripts/suppliers/erco_harvest.py      # קטלוג → data/materials/raw/
python scripts/suppliers/erco_units.py        # יחידות מדויקות מדפי המוצר
python scripts/suppliers/build_materials_db.py  # raw → המאגר המנורמל
node --test tests/materials.test.mjs          # שומרי הסף
```

שלושתם resumable — נפילה באמצע לא מתחילה מהתחלה.

## שלוש אזהרות שחייבות להישאר צמודות למספרים

1. **המחירים במאגר הם לפני מע"מ.** באתר של ארכה הם מוצגים כולל מע"מ (18%);
   הנרמול מחלק. `meta.price_basis = "retail_ex_vat"` הוא הצהרה, ובדיקה
   ב-`tests/materials.test.mjs` נכשלת אם מישהו משנה את זה בשקט.
2. **זה מחיר קמעונאי, לא מחיר קנייה של קבלן.** חשמלאי קונה בהנחת סוחר —
   בדרך כלל 10-35% מתחת. הבלוק שנשלח למודל אומר לו את זה במפורש, ומחייב אותו
   לנקוב באיזו הנחה הניח.
3. **יחידת המידה לפעמים משוערת.** ארכה עצמו כותב בעמוד המוצר "המחיר... והוא
   למטר או ליחידה" — העמימות היא במקור. לכן כל שורה נושאת `unit_src`:
   `page` (נקרא מדף המוצר), `name` (נאמר בשם הפריט), `category` (הוסק
   מהקטגוריה). `erco_units.py` מריץ קריאת-דף אמיתית על המשפחות שבהן
   מטר-מול-יחידה משנה את ההצעה (כבלים, מובילים, הארקות).

   ה-731 פריטים שנקראו מהדף הם גם **מבחן** לכללים: הבילד מחשב את אחוז ההתאמה
   בין מה שהכללים היו מנחשים לבין מה שהדף אומר, כותב אותו ל-`meta.unit_accuracy`,
   ומסרב לכתוב את הקובץ מתחת ל-90%. נכון להיום: **94.1%**. בלי המדד הזה אי אפשר
   לדעת אם 5,216 היחידות שהוסקו מקטגוריה טובות או זבל — הפלט נראה זהה כך או כך.
   המדידה הזו היא שהעלתה את הדיוק מ-86% (העלאת "אלקטרודה 198 ₪ **למטר**") ל-94%.

## איך הבוט משתמש בזה

`functions/api/chat.js` מוסיף בלוק DATA לכל שיחת תמחור: שתי הודעות המשתמש
האחרונות הופכות לשאילתה, `_materials.js` מדרג את הקטלוג לקסיקלית, ו-45 הפריטים
הרלוונטיים נכנסים לפרומפט יחד עם שלוש האזהרות שלמעלה. אם אין התאמה — לא נשלח
כלום, ולא משלמים טוקנים.

החיפוש לקסיקלי ולא וקטורי בכוונה: השאילתות הן קיצורי-מקצוע ("כבל 5x6",
'מא"ז 3x25'), והחלק שמבדיל הוא בדיוק המספר והדגם. חיפוש וקטורי מטשטש דווקא את
זה, עולה קריאת API בכל תור, ומוסיף אינדקס שני לתחזק.

### API

```
GET /api/materials?q=כבל 5x6            → פריטים תואמים (JSON)
GET /api/materials?q=...&format=block   → הבלוק המוכן לפרומפט (טקסט)
GET /api/materials?sku=5951160          → פריט אחד לפי מק"ט
GET /api/materials?cat=כבלי חשמל        → עיון בקטגוריה
GET /api/materials?taxonomy=1           → כל הקטגוריות + טווחי מחיר
GET /api/materials?meta=1               → טריות המאגר וגודלו
```

## רענון

מחירים זזים. `.github/workflows/materials-refresh.yml` מריץ את כל השרשרת פעם
בשבוע, מריץ את הבדיקות, ומקומיט רק אם הן עברו. אם ארכה יסגור את ה-GraphQL,
ה-workflow ייכשל ברעש — וזה בדיוק מה שצריך לקרות, כי הכשל השקט (מאגר ישן
שנראה תקין) הוא היקר.

## מה עוד לא נעשה

* ספקים נוספים — כרגע ארכה בלבד. שני ספקים היו נותנים לבוט פיזור שוק ולא
  מחירון אחד. ראה `BACKLOG.md`.
* חיבור ל-UI של טאב "מאגר מחירים" ב-`/sale/` (כרגע ה-API קיים, המסך עדיין לא
  צורך אותו).
