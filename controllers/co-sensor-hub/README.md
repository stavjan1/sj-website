# co_core — מנוע הבקרה של רכזת CO לחניון

C99 טהור. אין malloc, אין מערכת הפעלה, אין נגיעה בחומרה — לכן הוא רץ **כמו שהוא**
על ESP32, STM32, PLC עם C, וגם על המחשב לצורך בדיקות.

```
co_core.h        הממשק — קונפיגורציה, קלט חיישנים, פלט
co_core.c        הלוגיקה: max-select, מדרגות, היסטרזיס, כשל בטוח, quorum, דרייבר מפוחים
test_co_core.c   50 בדיקות שמדמות תרחישי חניון אמיתיים
build.sh         בונה ומריץ
```

## הרצה

```bash
./build.sh
```

## הרעיון בשורה אחת

```
קריאות חיישנים  ->  co_zone_tick()  ->  demand 0..100%  ->  co_fan_apply()  ->  רלאים / VFD
```

הליבה לא יודעת מה זה "מהירות נמוכה". היא מחזירה אחוז. הדרייבר מתרגם אותו לפי פרופיל
המפוח (מהירות אחת / 2 / 3 / VFD), ולכן אותו קוד רץ בכל פרויקט בלי לגעת בו.

## מה שהמנוע מבטיח (וכל אחד מהם מכוסה בבדיקה)

- **מדרגות לפי התקן** — 30 ppm / 5 דק' → 60 / 2 דק' → 120 / 30 שנ' → 200 מיידי
- **max-select** — חיישן אחד גבוה מספיק כדי להפעיל מפוחים
- **quorum לפינוי** — פינוי דורש הסכמה של 3 חיישנים, אוורור לא
- **חיישן סורר** — קריאה גבוהה בהרבה מהשכנים ⟵ דגל תקלה, לא אירוע
- **היסטרזיס + זמן ריצה מינימלי** — מגענים לא מרצדים
- **כשל בטוח** — אובדן כל החיישנים ⟵ מפוחים על 100%, לא כבויים
- **ממוצע 30 דק'** — הנתון הרגולטורי, עם דגל חריגה
- **מפוח עשן משותף** — הבקר חוסם את עצמו מתחת למהירות הגבוהה

## מה עוד לא בפנים (בכוונה — תלוי חומרה)

קריאת 4–20mA / Modbus, שעון אמת, יומן אירועים מתמיד, טסט מפוחים שבועי, ממשק משתמש.
כל אלה נכתבים מעל הליבה אחרי שנחליט על הפלטפורמה.
